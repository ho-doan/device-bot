# QC Web và truy cập LAN — ghi nhận sơ bộ

- Ngày: 2026-11-12. **DEFERRED — kiểm tra và ghi chú, chưa triển khai/chưa đổi bind**.

## Mục tiêu người dùng đã xác nhận

- **Cả QC và robot-report đều phục vụ qua web ở IP LAN**, để máy khác trong cùng mạng mở trình duyệt và sử dụng từ xa.
- QC: xem thiết bị, thao tác/điều khiển, xem Live, import/export và chạy YAML qua backend trên máy chủ.
- robot-report: xem/tải báo cáo và sử dụng chức năng quản lý từ xa theo quyền được cấp. Cần bổ sung xác thực/quyền cho chức năng ghi đang giới hạn localhost.
- Backend native và thiết bị nằm trên máy chủ; máy truy cập chỉ cần trình duyệt. Các thao tác điều khiển áp dụng lên thiết bị/backend được kết nối, không tự điều khiển máy đang mở trình duyệt.
- Hướng URL dự kiến: `http(s)://<IP-LAN>:<port>/qc/` và `/reports/`, API cùng origin. Đây là đề xuất bố trí, chưa triển khai. Không yêu cầu mở ra Internet.

## Kết luận

- Đưa QC Flutter lên web sẽ đơn giản hóa việc phân phối UI cho Windows/macOS/Linux (Ubuntu là một bản Linux). Máy người dùng mở trình duyệt; máy chạy Device Bot vẫn cần backend native, driver và quyền hệ điều hành tương ứng. Web không tự bổ sung driver Linux hay drag/swipe macOS.
- **Không cần viết thêm một MCP HTTP server từ đầu.** Hiện đã có `/mcp` và `/admin/*` trong `mcp-server`, QC cũng đang dùng chúng. Cần làm client tương thích trình duyệt và cách phục vụ UI/API.
- **8765 hiện là robot-report (báo cáo/history), không phải QC Flutter.** 3337 mới là MCP HTTP prod; dev dùng 8766/3338.

## Đã xác nhận

- `flutter build web --no-pub` **thành công**, tạo `server/flutter_app/build/web`. Chưa chạy kiểm thử UI/API/video trong trình duyệt; các nhánh `dart:io` vẫn cần thay thế cho runtime web.
- `lsof`: cả 8765 và 3337 đang bind `127.0.0.1`. `/health` trên localhost:8765 trả `service: robot-report`; gọi qua IP LAN của máy thất bại kết nối. Nguyên nhân trực tiếp hiện tại là bind loopback, chưa cần quy cho CORS/firewall.
- `launcher.rs:131` cố định địa chỉ report ở `127.0.0.1`; biến môi trường chỉ đổi port. `robot-report start --listen 0.0.0.0:8765` đã được hỗ trợ nếu chạy trực tiếp, nhưng cần xử lý tiến trình đang chiếm port khi triển khai sau.
- Report có chủ ý chỉ cho localhost thêm project/import history; mở bind LAN mới cho đọc/tải, không tự mở quyền ghi (`robot-report/src/http.rs:80–114`).
- MCP HTTP đã nhận `--listen HOST:PORT` và có bearer auth. Thử preflight `OPTIONS /mcp` với Origin khác port trả **405**, không có header CORS. Web khác origin chưa gọi được API này theo cấu hình hiện tại.

## Phần còn thiếu để phục vụ QC và report qua LAN

1. Thay `dart:io HttpClient` trong `mcp_client.dart` bằng transport hỗ trợ browser; giữ nguyên initialize/session/tools contract và luồng SSE.
2. Tách đọc token từ file local (`local_connection.dart`) và lưu recording bằng `File/Directory/Platform.environment` (`live_recording.dart`). Web cần kết nối/xác thực qua UI hoặc session và export bằng tải file; không nhúng token dùng chung vào bundle web.
3. Chọn **cùng origin** cho `/qc/`, `/mcp`, `/admin/*` (serve static hoặc reverse proxy) để giảm cấu hình CORS. Nếu tách origin: bổ sung OPTIONS, origin allowlist, cho phép các header cần dùng và expose `mcp-session-id`.
4. URL API phải trỏ máy backend; `127.0.0.1` trong trình duyệt máy khác là chính máy đó. Không giữ mặc định localhost khi dùng từ xa.
5. Kiểm tra riêng import/export YAML, WebRTC/video qua LAN (ICE/đường media), semantics và keyboard trong browser. Build thành công chưa chứng minh các luồng này hoạt động. HTTPS cần cho những tính năng browser yêu cầu secure context; HTTP IP LAN không có ngoại lệ tin cậy như localhost.
6. Nếu tích hợp vào report: xem lại router, quyền truy cập và CSP hiện chỉ cho tài nguyên/kết nối cùng origin. Giữ auth khi mở điều khiển qua LAN; chưa yêu cầu public Internet.
7. Bổ sung cấu hình bind/URL LAN cho launcher, phục vụ cả hai UI và phân quyền quản lý report từ xa. Xác minh từ máy thứ hai rằng tải được UI, gọi được API, điều khiển đúng thiết bị, chạy/export YAML và dùng report; không chỉ kiểm tra localhost trên máy chủ.
