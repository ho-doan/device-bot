# Kiểm kê Python để chuẩn bị refactor

Ngày khảo sát: 2026-11-16. Repository: `device_robot`.

## Phạm vi và kết luận

Còn **18 file Python được Git quản lý**. Inventory này chỉ liệt kê các file và vị trí vẫn phụ thuộc Python; mục đã xóa hoặc chuyển xong được bỏ khỏi danh sách.

Ngoài nguồn dự án, hiện có 3 file Flutter SDK/vendor và 13 Chrome wrapper Python trong artifacts. Các nhóm này có chủ sở hữu riêng; không tính vào 18 file nguồn cần refactor. Harness debug tạm nằm ngoài inventory sản phẩm và không được đưa vào commit.

Danh sách nguồn lấy từ `git ls-files '*.py'`; đối chiếu thêm file ẩn/ignored và lời gọi Python trong workflow, shell, Rust. Không liệt kê từng file của dependency/cache trong `node_modules`, `target`, `.venv`, `venv`, `build`, `.dart_tool`, `.git`, `.codegraph`. Submodule `astrotalk` không có file `.py` được Git quản lý tại thời điểm khảo sát. Số file trong artifacts có thể tăng sau mỗi lượt chạy.

**Server đã chạy được flow bằng Rust**: CLI `device-bot run` chuyển tới `robot-flow`; MCP `mobile_run_flow` dùng `FlowRunner` trực tiếp. Nhiều script Python chỉ chuẩn bị môi trường hoặc kiểm tra kết quả. Điểm phụ thuộc Python trong chức năng server đáng chú ý nhất là **cấu hình signing XCTest iOS**: có API/CLI Rust nhưng phần cập nhật project vẫn gọi script Python.

“Chưa có bản thay thế” trong bảng là kết quả đối chiếu các entry point đã đọc, không đồng nghĩa server thiếu chức năng điều khiển thiết bị. Các công việc build/release, fixture và kiểm thử nên có công cụ Rust dành cho phát triển hoặc integration test tương ứng.

## Những chức năng thực sự còn thiếu bản Rust độc lập Python

1. **Signing iOS runtime:** chọn team theo đầy đủ luật và sửa project Xcode atomically. Có public CLI/API nhưng vẫn chạy Python bên dưới. Đây là phần cần thay trong server/driver.
2. **Điều phối kiểm thử:** setup/teardown backend, QC, browser, fixture HTTP và file chooser, report seed, restart, fault injection, remote proxy, event/history/download/replay verification. Cần công cụ kiểm thử Rust; không cần đưa quyền tự kill/restart server vào một flow đang chạy trên chính server đó.
3. **Release/asset tooling:** archive layout, version preflight, macOS distribution app, icon rendering. Cần công cụ build Rust; không phải missing MCP tool.
4. **Fixtures/tests dùng interpreter:** fake MCP stdio, fake native command và fixture signing. Cần thay bằng Rust test helper và giữ các assertion tương ứng.
5. **Scaffold generator:** không cần bổ sung server capability để xóa ba script tạo YAML/CASES một lần. Đầu ra placeholder phải được hoàn thiện/kiểm thử, không trở thành PASS chỉ vì đã bỏ generator.

Các hành động YAML chưa được schema hiện tại hỗ trợ như `assert_file_downloaded` không tự xuất hiện sau khi đổi harness sang Rust. Cần quyết định bổ sung assertion đó vào `robot-flow` hay đặt kiểm tra ở harness. Tương tự, các MCP tool như `kill_process`, `fixture_file_chooser`, `mobile_minimize_window` cần đối chiếu nhu cầu và API riêng; việc Python gọi tên tool không chứng minh tool tồn tại.

## Bằng chứng về ranh giới hiện tại

- [CLI dispatch](../server/crates/mcp-server/src/commands.rs): `Command::Run` gọi launcher, cấu hình signing gọi `robot_ios_real::configure_xctest_signing`.
- [MCP flow tool](../server/crates/mcp-server/src/tools/flow.rs): `mobile_run_flow` compile và chạy bằng `FlowRunner` Rust trong case session.
- [Schema flow](../server/crates/robot-flow/src/schema.rs): danh sách action hợp lệ và giới hạn timeout; không có `assert_file_downloaded`.
- [HTTP MCP client](../server/crates/robot-flow/src/http_mcp.rs): nhận loopback HTTP, kết nối từng exchange và dùng MCP session ID; không có cơ chế phục hồi qua restart trong bản hiện tại.
- [Signing Rust](../server/crates/robot-ios-real/src/lib.rs) → [shell signing](../server/crates/robot-ios-real/xctest-runner/configure_ios_signing.sh) → Python ở mục 18.

## Điều kiện để refactor không mất chức năng

### Flutter example: chuyển CI sang YAML

- CI GitHub/GitLab app-root hiện chạy `ci/validate.sh`, shell bootstrap/CI tests và `ci/run_yaml.sh`; không còn caller Python trong đường CI example.
- Chín `it-01.yaml`..`it-09.yaml` là nguồn scenario; đã bỏ các shell scenario trùng cùng helper MCP/test cũ. Shell còn build/install/cold-stop và kiểm tra evidence CI; Windows fixture lifecycle và JUnit fallback do `robot-project` xử lý bằng Rust.
- `automation_test/ci/mobile-yaml.gitlab-ci.yml` vẫn là include monorepo opt-in/manual chạy một case với external setup; after_script dùng `device-bot project ensure-report`. CI chính chạy đủ chín case qua Rust runner.
- Profile mặc định của CI là `targets-semantics.yaml` cho fixture hiện tại. JSON/JUnit native giữ PASS/PARTIAL và limitations; wrapper kiểm report, ffprobe/full decode và QA_REVIEW PENDING. Report preflight/warmup không tính vào GitLab test results.
- Rust tests và shell fixtures xác minh hợp đồng runner/CI, không chứng minh app/driver thật. Simulator có evidence YAML lịch sử; Android/Windows và physical iOS vẫn cần live verification đúng target/build.
- Workflow dưới `examples/flutter_app/.github/workflows/` không được GitHub tự khám phá từ repository root; GitLab cần chọn/include config example. Đây là cấu hình dành cho khi example được dùng như project CI riêng.

- `.draft` là hàng rào CI: chỉ YAML đã xác minh mới vào tập mặc định. Hiện `run.py` chọn từ CASES mà không lọc theo file tồn tại/suffix; việc đặt `.draft` ngăn thực thi được nội dung nhưng có thể làm CI báo lỗi thiếu file. Cần lọc danh mục CI rõ ràng khi thay runner.
- Chạy draft phải là lựa chọn tường minh của người kiểm thử. Chỉ promote sau khi flow và evidence checks đều PASS; YAML parse được chưa đủ.
- Crate `automation-test-harness` đã được commit nhưng chỉ là launcher thử nghiệm có kiểm soát draft. Nó chưa thay setup, fixtures, verification và cleanup trong `run.py`; không coi crate này là bản port hoàn tất.
- Thay implementation, tests, caller CI/shell và release assets theo từng nhóm. Chỉ xóa Python dependency của job khi không còn caller trực tiếp, Python nhúng hoặc script sinh ra.
- Dùng danh sách 18 file hiện còn làm checklist; rà lại source/CI bằng tìm kiếm `python`, `.py` và shebang sau refactor. SDK/vendor và artifacts là các nhóm sở hữu riêng. Xóa mục khỏi inventory khi file hoặc dependency tương ứng thực sự không còn.

Tài liệu này là khảo sát tĩnh từ source và caller; không chạy script generator, packaging hay bài kiểm thử thiết bị trong lượt kiểm kê.
